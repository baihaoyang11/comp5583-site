Interests

I came into this programme from the engineering side, and the part I actually enjoy is what happens after the demo works: finding out why it stops working when the data changes. At the moment that means retrieval systems whose answers can be checked against the passage they came from, evaluation that still means something on a different dataset, and the unglamorous work of making a model usable by someone who did not write it.

Everything I know about this came from coursework I had to debug myself, so I trust a small experiment I can rerun more than a large claim I cannot.

02Projects

Coursework

Four models, two datasets — and where every number came from

Four models that are usually described separately, run under one protocol each: on Digits4000 a hand-written NumPy MLP and a PyTorch CNN, on multilingual toxicity a TF-IDF + logistic regression baseline and a fine-tuned multilingual DistilBERT. Every figure on this page was retrieved from a result file by a small retriever rather than typed from my notes; the citation next to each one names the chunk it came from.

My contribution. Wrote the MLP and its backward pass by hand with no automatic differentiation, built the two corrupted test suites, ran the DistilBERT fine-tuning and the threshold protocol, ran the loss ablation, and wrote the retriever that produced the citations on this page.

Multilingual toxicity

The other two models were not on digits, so they have no place in that table. On 4000 test comments, 615 of them toxic, TF-IDF with logistic regression reached a ROC-AUC of 0.5796c50 and an F1 of 0.1645c50 on the toxic class; the fine-tuned multilingual DistilBERT reached 0.7638c51 and 0.3236c51. Then the part that matters: dropping the inverse-frequency class weighting lifted that F1 to 0.4957c92 and the AUC to 0.7812c92.

So the weighted model I shipped was the worse one. It reached recall 0.8748c51 at precision 0.1985c51 — it moved the operating point rather than improving the classifier, and F1 fell because of it. Threshold fixed on the English validation set in every run, never on the test set.

Training ran on GPU (NVIDIA GeForce RTX 3070 Ti Laptop GPU), seed 42, with comments truncated at 128 tokens and 4 epochs; the MLP took 2.27 s, the CNN 25.03 s and DistilBERT 147.58 s. Every figure in this paragraph and the two above is a chunk read out of a result file at build time — the build fails if a value cannot be retrieved, so a number on this page cannot be stale.

Proposed

Citation-first Q&A over course notes

The same idea applied to reading: answer questions over my own lecture PDFs so that every sentence in the answer points at the passage it came from. The retriever above already does this on six JSON files, which is how I know the hard part is not the retrieval.

Planned contribution. Chunking by section heading, hybrid BM25 + dense retrieval, and a 40-question evaluation set built from questions I have actually asked. Measure citation precision with and without retrieval, so the retrieval step has to justify itself.

Because the evaluation set is the part I have not finished. A retrieval demo without a fixed question set only shows that retrieval returns something; it cannot show that the returned passage is the one that supports the answer. The version above is a weak form of the test: 26 questions, 26 resolved, but I chose the questions knowing the answers were in the corpus, which is not the same as being hard to find.
